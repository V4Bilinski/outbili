# Checklist — Diagnóstico de Travas

Validar que o diagnóstico de travas foi executado com rigor antes de avançar para a proposta DR.

## TOC Aplicado
- [ ] Metodologia Theory of Constraints aplicada ao negócio
- [ ] Gargalo principal do sistema identificado e documentado
- [ ] Causa raiz do gargalo mapeada (não apenas sintoma)
- [ ] Relação de causalidade entre trava e perda de receita estabelecida

## Identificação do Gargalo
- [ ] Gargalo único prioritário definido (não múltiplos simultâneos)
- [ ] Evidências quantitativas do gargalo coletadas (dados, métricas, benchmarks)
- [ ] Impacto financeiro estimado do gargalo (R$/mês ou % receita)
- [ ] Stakeholders que confirmam o gargalo identificados

## Coleta de Dados
- [ ] Dados de tráfego coletados (sessões, fontes, CAC)
- [ ] Dados de engajamento coletados (taxa de abertura, tempo na página, scroll depth)
- [ ] Dados de conversão coletados (taxa por etapa do funil)
- [ ] Dados de retenção coletados (churn, LTV, NPS)
- [ ] Histórico mínimo de 90 dias disponível
- [ ] Dados comparados com benchmark do segmento

## Classificação da Trava (T1–T8)
- [ ] Trava classificada na categoria correta (T1 a T8)
- [ ] Justificativa da classificação registrada com evidências
- [ ] Travas secundárias documentadas (se existirem)
- [ ] Sequência de resolução priorizada (qual trava atacar primeiro)

## Validação do Diagnóstico
- [ ] Diagnóstico revisado por pelo menos um agente sênior do squad
- [ ] Cliente/stakeholder confirmou os dados e a leitura do problema
- [ ] Diagnóstico final documentado no template `diagnostico-travas-tmpl.md`
- [ ] Score de confiança do diagnóstico registrado (Alto / Médio / Baixo)
